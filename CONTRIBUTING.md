# Welcome to the gematik contributing guide

Thank you for investing your time in contributing to our projects!

In this guide, you will get an overview of how to contribute to this tap by opening an issue and creating a pull request.

## Reporting a security vulnerability

Please report vulnerabilities as described in the [Security Policy](./SECURITY.md).

## New contributor guide

To get an overview of the project, read the [README](./README.md).

Formulas and casks in this tap are generated by the release process of each application and pushed here when it is released. A fix to one of them belongs in the template in the application's repository, which is named in the formula's `homepage`. Otherwise the next release overwrites it. Issues with an application itself belong in that application's repository.

## Getting started

### Issues

#### Create a new issue

If you spot a problem with the tap, search if an [issue](https://github.com/gematik/homebrew-tap/issues) already exists.
If a related issue doesn't exist, you can open a new issue.

#### Solve an issue

Scan through our existing issues to find one that interests you. If you find an issue to work on, you are welcome to open a PR with a fix.

### Make changes

1. Fork the repository and create a branch from `main`.
2. Check every formula or cask you changed:
   ```
   brew style gematik/tap
   brew audit --strict --online --formula gematik/tap/<formula>
   brew install gematik/tap/<formula> && brew test gematik/tap/<formula>
   ```
3. Record changes to the tap itself in [ReleaseNotes.md](./ReleaseNotes.md).

### Commit your update

Commit the changes once you are happy with them. Use a subject in the imperative mood. A formula update is committed as `<name> <version>`.

### Pull Request Process

- When you're finished with the changes, create a pull request against `main`.
- Describe what changed, why, and how it was verified.
- Don't forget to [link the PR to the issue](https://docs.github.com/en/issues/tracking-your-work-with-issues/linking-a-pull-request-to-an-issue) if you are solving one.
- Once you submit your PR, a project team member will review your proposal. We may ask questions or request additional information.
- We may ask for changes to be made before a PR can be merged, either using [suggested changes](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/reviewing-changes-in-pull-requests/incorporating-feedback-in-your-pull-request)
  or pull request comments. You can apply suggested changes directly through the UI. You can make any other changes in your fork, then commit them to your branch.
- As you update your PR and apply changes, mark each conversation as [resolved](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/reviewing-changes-in-pull-requests/commenting-on-a-pull-request#resolving-conversations).
